实施时与草案的不同：

- 重复区域按整个图集判断，不只是同一页面：Spine 按名称在整个图集中查找区域。
- 无法识别的字段只对页面报告。区域中的其他字段是 Spine 的“名称/值”附加数据，不报告。
- 页面文件名中的 `%`、`?`、`#` 编码后报告：宿主把地址当作 URI，会解码百分号、丢弃 `?` 与 `#` 之后的部分。

## 1. 目标

路线图把“第二种格式”列为验证组成契约是否通用的下一步。glTF 只有“一个文件 → 它直接写出的外部文件”这一层引用；Spine 的导出物是一组靠约定和名称连在一起的文件：

```text
hero.json（或 hero.skel）  骨骼、插槽、皮肤、附件、动画
   │  按同名约定配对，文件里不写图集的名字
   ▼
hero.atlas                 页面与区域；附件按“区域名”找到区域
   │  页面行写出图片文件名
   ▼
hero.png、hero2.png        贴图页
```

这个插件有两个目的：

- 让使用者在 Vormio 中看懂 Spine 资产的组成：骨骼、皮肤、附件、动画，以及图集用到了哪些贴图页。
- 把现有契约表达不了的地方，整理成带真实场景的 Core 需求（§8）。插件内部不绕过这些边界。

插件 ID `vormio-plugins.spine`，目录 `plugins/spine/`，首个版本 0.1.0，显示名称“Spine 骨骼动画”（名称中使用商标的问题见 §10）。

## 3. 图集分析器（0.1.0 交付）

**格式**：libGDX 文本图集，Spine 3.x 与 4.x 的两种写法都支持：

- 4.x：区域使用 `bounds`、`offsets`，页面可以有 `pma`、`scale`。
- 3.x：区域使用 `xy`、`size`、`orig`、`offset`。文件开头可以有空行。

分析只需要页面名、区域名与 `index`，其他字段只检查格式，不解释。

**子资源**：

| 类别 | key              | 名称                                     | 上级     |
| ---- | ---------------- | ---------------------------------------- | -------- |
| 页面 | `pages/<序号>`   | 页面行写的图片文件名                     | —        |
| 区域 | `regions/<序号>` | 区域名；`index` ≥ 0 时写成“名称（帧 N）” | 所在页面 |

**引用**：每个页面引用它的图片，`uri` 为页面行原文，角色“贴图页”，证据为“第 N 行”。由宿主相对图集文件解析；`../` 与子目录照常处理。

**诊断**：

- 同一页面中重复的“名称 + index”：警告，两项都保留，key 不同。
- 无法识别的字段：信息。
- 页面缺少 `size`：信息，只有渲染时才需要。
- 不是图集文本（例如第一个非空行后紧跟的不是“键: 值”）：分析失败，并给出行号。

**上限**：与 SDK 的 `reportLimits` 一致。子资源超出时先保留全部页面与页面引用，再按出现顺序保留区域，报告标为部分完成。名称按 UTF-8 截断，去掉控制字符。

**读取**：通过 SDK 读取整个文件，不读配套文件，所以不声明 `companionFormats`。

## 4. 骨骼 JSON 解析（0.1.0 完成代码与测试，0.4.0 声明）

识别条件：顶层是对象，有 `skeleton.spine` 版本字符串，并且有 `bones` 数组。不满足时返回“不是 Spine 骨骼文件”（`NotSpineError`）；0.4.0 起三个扩展点都把它映射为 `notApplicable()`（§13）。

**子资源**（key 用序号，名称取文件中的 `name`）：

| 类别                                  | 来源                                                                                        | 上级     |
| ------------------------------------- | ------------------------------------------------------------------------------------------- | -------- |
| 骨骼                                  | `bones`                                                                                     | 父骨骼   |
| 插槽                                  | `slots`                                                                                     | —        |
| IK 约束、变换约束、路径约束、物理约束 | `ik`、`transform`、`path`、`physics`（物理约束为 4.2）                                      | —        |
| 皮肤                                  | `skins`                                                                                     | —        |
| 附件                                  | `skins[].attachments.<插槽>.<附件>`，类别细分为区域、网格、链接网格、包围盒、路径、点、裁剪 | 所在皮肤 |
| 事件                                  | `events`                                                                                    | —        |
| 动画                                  | `animations`                                                                                | —        |

附件的名称写附件键。用来查找图集区域的名字（`path`，没有时就是附件名）与附件键不同时，写成“附件键（区域 xxx）”。4.1 起的序列附件写成“区域 xxx（N 帧）”。

**内部引用**（`key` 加 `from`）：

| 发起者 | 目标                                                     | 角色               |
| ------ | -------------------------------------------------------- | ------------------ |
| 插槽   | 所在骨骼                                                 | 所在骨骼           |
| 约束   | 骨骼与目标（骨骼或插槽）                                 | 约束骨骼、约束目标 |
| 皮肤   | 皮肤专属的骨骼与约束                                     | 皮肤包含           |
| 附件   | 所在插槽；链接网格的父网格；裁剪附件的结束插槽           | 对应的角色名       |
| 动画   | 时间轴涉及的骨骼、插槽、约束、事件；形变时间轴涉及的附件 | 动画目标           |

同一对象之间、同一角色的引用只报告一次。证据写 JSON 路径，例如 `/skins/0/attachments/head/head`。

**文件引用**：0.1.0 不报告。

- 图集配对见 D3；0.6.0 起同名图集作为推断的引用报告（§14）。
- `skeleton.images`、`skeleton.audio` 是编辑器中的非必需路径，相对于什么位置还没有用真实导出确认（§10）。事件的 `audio` 只写进事件名称，不报告。

**诊断**：

- 指向不存在的骨骼、插槽、皮肤或附件：引用略去，记警告。
- 骨骼层级成环：断开一处，记警告。
- 版本高于 4.2：警告。
- 3.7 及更早（`skins` 是对象）：分析失败，并说明原因。

**上限**：超出时先保留骨骼、插槽、皮肤，再按附件、动画、约束、事件的顺序略去，报告标为部分完成。

## 6. 测试素材

`scripts/make-fixtures.ts` 生成 `fixtures/spine/`，复用现有的 PNG 编码函数，许可与 glTF 素材相同：

- `basic/`：4.2 格式的骨骼 JSON，含区域、网格、链接网格与裁剪附件，两个皮肤、一个物理约束、事件与两段动画；4.x 图集，两页贴图。
- `legacy/`：3.8 骨骼 JSON 与 3.x 写法的图集。
- `layout/`：贴图页在 `../textures/` 下，文件名带空格。
- `problems/`：
  - 缺失一页贴图。
  - 重复区域。
  - 截断的图集。
  - 指向不存在骨骼的插槽。
  - 3.7 格式的骨骼（`skins` 为对象）。
  - 普通的非 Spine JSON。
- `preview/`（0.3.0）：给骨骼预览的二进制骨骼，3.8 与 4.0 至 4.3 各一份同样的小人偶，每个附件一种颜色（3.8 的图集用 3.x 写法）；以及缺图集、缺贴图页、截断、没有附件、5.0 与 3.7 文件头的问题素材。0.4.0 加入同一个人偶在每个版本的骨骼 JSON、一份 3.7 骨骼 JSON，以及三份不是 Spine 的 JSON（对象、数组、带注释的文本）。
- 超上限的图集在测试中生成，不入库。

真实导出（Spine 官方示例或使用者自己的项目）只在手工验收时临时放进关联文件夹，结果写进提交说明，文件不入库。

## 7. 测试与验收

- **Node 测试**：
  - 图集解析：两种写法、多页、`index`、重复与损坏输入、上限与截断。
  - 骨骼解析：各类别与层级、内部引用、诊断、版本判断、非 Spine JSON。
  - 每份报告都用 SDK 的 `parseReport` 校验。
- **Chromium 测试**：分析器页面在替身宿主中返回报告，读取失败时给出原因。
- **Core 0.0.3 手工验收**（开发目录）：
  1. 启用时确认框只列出“组成分析：atlas”。
  2. 图集列出页面与区域，贴图页已解析；点击跳转到贴图，显示“被 N 个文件引用”。
  3. 删除一页贴图并重新扫描，图集显示缺失引用；恢复后复原。
  4. 原文件不变。
- **Core 0.0.4 完成后补验**：移动贴图页，引用显示“已移到”。这同时作为 0.0.4 移动识别的第二个真实场景。

## 10. 开放问题

1. **商标**：插件名称中使用 “Spine” 是否只是说明用途？需要你确认，必要时咨询法律意见。本计划只摘录条款，不构成法律判断。
2. **开发与测试是否也算“使用者”**：第二段要求产品的每个使用者都持有许可证，开发与测试时也在运行 spine-ts。Nate 在 Flame 的答复中没有这样要求，但没有明说。2026-10-14 决定不等答复，默认使用者自带许可证。
3. **官方目录**：已决定（2026-10-14），在 R4（#5）之前上架，0.4.0 随目录序号 2 发布。目录不另外展示许可：要求写在 manifest `description` 的第一句，插件窗口的目录卡片上可见；安装与启用的确认框仍然看不到，见问题 4。
4. **启用确认框**：已在 Core `0c7fee0` 上确认，安装与启用确认框只列出权限，不显示 `description`；安装时“同时启用”默认勾选。Core 0.0.6 的验收（§13）中也一样。所以许可要求现在只在插件窗口、README 与骨骼查看器中可见，要靠 R4（#5）放进启用路径。

5. **路径的基准**：`skeleton.images` 与 `skeleton.audio` 在真实导出中相对于什么位置？需要用一份真实导出确认，再决定是否报告为文件引用。
6. **4.2 之后的格式变化**：骨骼 JSON 的解析在 4.3 发布后重新核对（骨骼预览已经用 4.3 运行时）。已知的一处：spine-core 4.3 的 JSON 读取器从顶层的 `constraints` 列表读取各种约束（每项带 `type`），不再读 `ik`、`transform`、`path`、`physics`，所以 4.3 骨骼 JSON 的组成分析列不出约束。0.4.0 照常附“比 4.2 新”的警告；要用一份 4.3 的真实导出确认之后再改解析。

**发现的宿主问题**（与“不适用”无关；这里没有修改 Core，Core 在 0.0.6 收尾时修复了两个问题，`166562d`）：

1. **插件缩略图按文件内容缓存**。`ThumbnailService` 的缓存键是“内容 SHA-256 + 提供者 + 插件摘要”，进行中的任务与内存里的失败也按它合并。插件按文件的位置与名字读取配套文件，内容相同、配套文件不同的两个文件因此共用一个结果。复现：`preview/` 中 `hero.skel`、`orphan.skel`、`torn.skel` 内容相同（素材脚本写的同一个人偶），只有 `hero.atlas` 存在；网格中三个都显示 hero 的缩略图，`orphan.skel` 与 `torn.skel` 应当失败（“找不到同名图集 orphan.atlas（文件不存在）”“贴图页无法读取：torn.png（文件不存在）”）。先问到哪一个，三个就都是它的结果。glTF 同理：两个相同的 `.gltf` 放在贴图不同的两个文件夹。
2. **页面因失败重建时，同时在处理的任务记为失败**。同一页面连续 3 次失败后宿主关闭它（`PluginJobPages.close`），页面上其他进行中的任务以 `JobCancelled('The plugin page closed')` 结束；分析队列会重试这种任务，缩略图服务把它当作这个文件的失败，直到重启。复现：新资源库只关联 `preview/` 的副本并启用插件（文件夹里有 5 个以上本来就会失败的骨骼），4 次中有 1 次 `knight.skel` 没有缩略图，详情栏“缩略图生成失败：The plugin page closed”，第一个骨骼缩略图页面只存在了 354 ms。原因文字是英文。

## 14. 同名图集作为推断的引用（0.6.0，试用中）

Core 为 R2（Vormio/Vormio-Core#2）发布了 SDK 预发布版 0.0.7-rc.1（npm 标签 `next`）：报告中带 `uri` 的引用可以有 `inferred`（推断依据，显示给使用者）。宿主把推断的引用与写明的引用分开显示，找不到目标时显示“未找到”，不算缺失引用；含推断引用的文件改名或移动后宿主重新分析。语义以 SDK README 的 “Inferred references” 为准。插件契约随之升到 `apiVersion: 3`。

**决定**（2026-10-14）：

| 编号 | 决定                                                                                                                    | 理由                                                                                                                           |
| ---- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| I1   | 只有骨骼 JSON 的分析器报告；二进制骨骼仍没有分析器                                                                      | Core 在 #2 中请插件线对 `json` 与 `skel` 都报告，但 `.skel` 没有组成分析（D4）；为它新增分析器扩展点是新的能力，不在这次试用中 |
| I2   | 只在骨骼有从图集取图的附件（区域、网格、链接网格）时报告                                                                | 没有这样的附件时运行时不需要图集，报告一个多半“未找到”的图集只会误导                                                           |
| I3   | 地址与骨骼预览读取的相同：`atlasName` 加 `fileUri`，两处共用 `src/skeleton.ts` 中的函数；不检查图集是否存在，也不读取它 | 宿主在查询时判断目标；分析器仍只读取骨骼本身，不声明配套格式                                                                   |
| I4   | 角色“图集”，依据“与骨骼文件同名”                                                                                        | 与插件其他显示文字一样用中文（SDK 的例子是英文）；依据说明为什么认为有这条关系                                                 |
| I5   | Spine 0.6.0、glTF 0.2.2（只改 manifest）；声明的格式与配套格式不变                                                      | 官方目录按“插件 ID + 版本”认包，同一版本不能以另一个 `apiVersion` 发布                                                         |

**试用**：本仓库的测试覆盖报告本身：区域、网格与链接网格附件需要图集，只有包围盒、点、路径与裁剪附件或没有附件时不报告；文件名中的 `%`、`#` 编码、只去掉最后一个扩展名；两个骨骼共用 `hero.atlas` 时只有 `hero.json` 推断到它；分析器页面在 Chromium 中按替身宿主给的文件名报告，不读取图集。每份报告都用 SDK 0.0.7-rc.1 的 `parseReport` 校验。已运行 `pnpm run typecheck`、`pnpm test`（Node 90 项、Chromium 54 项）与仓库文件的 Prettier 检查。

**未验证**：宿主中的显示与行为（推断引用的分组、“未找到”、不计入缺失引用、改名后重新分析）。没有发布的 Core 0.0.7 可用，手工验收由 Core 按 #2 的验收条件进行；结果与发现的宿主问题回到 #2。Core 0.0.7 正式发布后，换成正式版 SDK，在发布版本上补做本仓库的手工验收再发布。
