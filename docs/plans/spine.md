实施时与草案的不同：

- 重复区域按整个图集判断，不只是同一页面：Spine 按名称在整个图集中查找区域。
- 无法识别的字段只对页面报告。区域中的其他字段是 Spine 的“名称/值”附加数据，不报告。
- 页面文件名中的 `%`、`?`、`#` 编码后报告：宿主把地址当作 URI，会解码百分号、丢弃 `?` 与 `#` 之后的部分。

## 1. 目标

路线图把“第二种格式”列为验证组成契约是否通用的下一步。glTF 只有“一个文件 → 它直接写出的外部文件”这一层引用；Spine 的导出物是一组靠约定和名称连在一起的文件：

```text
hero.json（或 hero.skel）  骨骼、插槽、皮肤、附件、动画
   │  按同名约定配对，文件里不写图集的名字
   ▼
hero.atlas                 页面与区域；附件按“区域名”找到区域
   │  页面行写出图片文件名
   ▼
hero.png、hero2.png        贴图页
```

这个插件有两个目的：

- 让使用者在 Vormio 中看懂 Spine 资产的组成：骨骼、皮肤、附件、动画，以及图集用到了哪些贴图页。
- 把现有契约表达不了的地方，整理成带真实场景的 Core 需求（§8）。插件内部不绕过这些边界。

插件 ID `vormio-plugins.spine`，目录 `plugins/spine/`，首个版本 0.1.0，显示名称“Spine 骨骼动画”（名称中使用商标的问题见 §10）。

## 3. 图集分析器（0.1.0 交付）

**格式**：libGDX 文本图集，Spine 3.x 与 4.x 的两种写法都支持：

- 4.x：区域使用 `bounds`、`offsets`，页面可以有 `pma`、`scale`。
- 3.x：区域使用 `xy`、`size`、`orig`、`offset`。文件开头可以有空行。

分析只需要页面名、区域名与 `index`，其他字段只检查格式，不解释。

**子资源**：

| 类别 | key              | 名称                                     | 上级     |
| ---- | ---------------- | ---------------------------------------- | -------- |
| 页面 | `pages/<序号>`   | 页面行写的图片文件名                     | —        |
| 区域 | `regions/<序号>` | 区域名；`index` ≥ 0 时写成“名称（帧 N）” | 所在页面 |

**引用**：每个页面引用它的图片，`uri` 为页面行原文，角色“贴图页”，证据为“第 N 行”。由宿主相对图集文件解析；`../` 与子目录照常处理。

**诊断**：

- 同一页面中重复的“名称 + index”：警告，两项都保留，key 不同。
- 无法识别的字段：信息。
- 页面缺少 `size`：信息，只有渲染时才需要。
- 不是图集文本（例如第一个非空行后紧跟的不是“键: 值”）：分析失败，并给出行号。

**上限**：与 SDK 的 `reportLimits` 一致。子资源超出时先保留全部页面与页面引用，再按出现顺序保留区域，报告标为部分完成。名称按 UTF-8 截断，去掉控制字符。

**读取**：通过 SDK 读取整个文件，不读配套文件，所以不声明 `companionFormats`。

## 4. 骨骼 JSON 解析（0.1.0 完成代码与测试，暂不声明）

识别条件：顶层是对象，有 `skeleton.spine` 版本字符串，并且有 `bones` 数组。不满足时返回“不是 Spine 骨骼文件”。R1 实现后，这个结果就是拒绝信号。

**子资源**（key 用序号，名称取文件中的 `name`）：

| 类别                                  | 来源                                                                                        | 上级     |
| ------------------------------------- | ------------------------------------------------------------------------------------------- | -------- |
| 骨骼                                  | `bones`                                                                                     | 父骨骼   |
| 插槽                                  | `slots`                                                                                     | —        |
| IK 约束、变换约束、路径约束、物理约束 | `ik`、`transform`、`path`、`physics`（物理约束为 4.2）                                      | —        |
| 皮肤                                  | `skins`                                                                                     | —        |
| 附件                                  | `skins[].attachments.<插槽>.<附件>`，类别细分为区域、网格、链接网格、包围盒、路径、点、裁剪 | 所在皮肤 |
| 事件                                  | `events`                                                                                    | —        |
| 动画                                  | `animations`                                                                                | —        |

附件的名称写附件键。用来查找图集区域的名字（`path`，没有时就是附件名）与附件键不同时，写成“附件键（区域 xxx）”。4.1 起的序列附件写成“区域 xxx（N 帧）”。

**内部引用**（`key` 加 `from`）：

| 发起者 | 目标                                                     | 角色               |
| ------ | -------------------------------------------------------- | ------------------ |
| 插槽   | 所在骨骼                                                 | 所在骨骼           |
| 约束   | 骨骼与目标（骨骼或插槽）                                 | 约束骨骼、约束目标 |
| 皮肤   | 皮肤专属的骨骼与约束                                     | 皮肤包含           |
| 附件   | 所在插槽；链接网格的父网格；裁剪附件的结束插槽           | 对应的角色名       |
| 动画   | 时间轴涉及的骨骼、插槽、约束、事件；形变时间轴涉及的附件 | 动画目标           |

同一对象之间、同一角色的引用只报告一次。证据写 JSON 路径，例如 `/skins/0/attachments/head/head`。

**文件引用**：0.1.0 不报告。

- 图集配对见 D3。
- `skeleton.images`、`skeleton.audio` 是编辑器中的非必需路径，相对于什么位置还没有用真实导出确认（§10）。事件的 `audio` 只写进事件名称，不报告。

**诊断**：

- 指向不存在的骨骼、插槽、皮肤或附件：引用略去，记警告。
- 骨骼层级成环：断开一处，记警告。
- 版本高于 4.2：警告。
- 3.7 及更早（`skins` 是对象）：分析失败，并说明原因。

**上限**：超出时先保留骨骼、插槽、皮肤，再按附件、动画、约束、事件的顺序略去，报告标为部分完成。

## 8. 给 Core 的需求草稿

以下需求在插件实现中确认场景后，按 Core 的流程提出，不在本仓库中修改 Core。

**R1：扩展点按内容声明“不是我的格式”。**

- 场景：Spine 骨骼、DragonBones、Lottie 都使用 `.json`。现在声明 `json`：
  - 每个 JSON 文件都会进入分析队列，非 Spine 文件显示分析失败或空的组成区；
  - 查看器会取代所有 JSON 的内置文本预览。
- 期望：分析器、缩略图和查看器可以返回“不适用”。宿主不记失败、不显示组成区，改用下一个提供者或内置预览；同一观察版本不再重复询问这个插件。
- 已提给 Core（Vormio/Vormio-Core#1）。Core 0.0.6 的计划只让分析器按内容拒绝，这是 0.4.0 的前提；缩略图与查看器的拒绝是 0.5.0 的前提。Core 计划写的理由之一是“骨骼的缩略图与查看器要等 R2 与 spine-ts 的许可条件”：现在许可方式已经决定，同名图集的读取也不需要 R2（§12），骨骼的缩略图与查看器就是真实使用方。

**R2：推断出的关系。**

- 场景：骨骼按同名约定使用 `hero.atlas`，文件里没有地址。
- 期望：报告中可以给出“推断引用”，与文件中写明的引用分开显示。推断引用找不到目标时不计入“缺失引用”，可以被人工关联覆盖。
- 这对应产品主旨中“区分包含、实际引用和人工关联”，以及路线图中的人工关联。

**R3：指向其他文件中子资源的引用。**

- 场景：骨骼附件 `head` 使用图集 `hero.atlas` 中的区域 `head`；图集被另一个报告分析。
- 期望：引用目标可以是“文件 + 该文件报告中的子资源名或 key”。宿主在两份报告之间连接，目标子资源不存在时显示为缺失。
- 这对应能力定义中的目标定义“跨插件的引用汇总”。Spine 是同一插件的两种文件，场景更简单，可以作为第一个使用方。

**R4：启用前同意第三方许可。**

- 场景：本插件包含的 Spine Runtimes 要求每个使用者都持有自己的许可证。现在启用确认框只列出能力与配套格式，manifest 也不能声明许可文本（未知字段会被拒绝）。
- 期望：manifest 可以声明包内的一份许可文本；启用时宿主展示它，使用者同意后才启用；同意的记录与权限指纹一起保存，许可文本变化时重新询问。
- 这是 GameMaker 对 Spine Runtimes 的做法，也适用于其他带类似条款的运行时。已提给 Core（Vormio/Vormio-Core#5）。

## 9. 许可与依赖

- **Spine Runtimes**（仓库 `EsotericSoftware/spine-runtimes`，许可 2025-04-05 版）。协议有两段：
  - 第一段：持有 Spine Editor 许可证的人，按 Spine Editor 许可协议第 2 节集成运行时，使用者不需要自己的许可证。
  - 第二段：其他人也可以集成运行时，条件是产品的每个使用者都自己持有 Spine Editor 许可证；再分发时附上协议与版权声明。
  - 分发方不持有许可证（2026-10-14 的决定），所以按第二段分发。产品是整个插件包：只用图集与组成分析的人也是使用者。Esoteric 的 Nate 在 2022 年答复 Flame 引擎时建议把含运行时的部分做成可选组件，许可只作用于它；本插件起初按此拆成两个插件，后来合并（见本文开头）。
  - 本插件要做的：插件包附上协议原文 `licenses/SPINE-RUNTIMES.txt`（构建时从 spine-webgl 包复制）；manifest 的 `description` 第一句写明许可要求；插件 README 与骨骼查看器底部也写明。插件无法核实使用者是否持有许可证。
  - 第 2.1(a) 节（重要且主要的功能）与第 12(e) 节是第一段的条件，按第二段分发时不涉及。
- **图集与骨骼 JSON 的解析**：不使用运行时，只依据 Esoteric Software 公开的格式说明与自己生成的素材。
- **依赖**：`@esotericsoftware/spine-webgl` 4.2.120 与 4.3.13（npm 别名 `spine-webgl-4.2`、`spine-webgl-4.3`，各带同版本的 spine-core），版本、许可与用途见插件 README。
- **素材生成器**：`scripts/fixtures/spine-binary.ts` 按运行时的二进制读取器写出 `.skel` 素材，是运行时的派生代码，受同一协议约束；它不进入插件包。
- **共用代码**：报告的截断、UTF-8 计量与名称清理和 glTF 插件相同，按仓库目录规划移到 `shared/`，glTF 插件随之改用，行为不变。

## 10. 开放问题

1. **商标**：插件名称中使用 “Spine” 是否只是说明用途？需要你确认，必要时咨询法律意见。本计划只摘录条款，不构成法律判断。
2. **开发与测试是否也算“使用者”**：第二段要求产品的每个使用者都持有许可证，开发与测试时也在运行 spine-ts。Nate 在 Flame 的答复中没有这样要求，但没有明说。2026-10-14 决定不等答复，默认使用者自带许可证。
3. **官方目录**（Core 0.0.5）：目录页面如何展示许可要求，是否要在 R4 之前上架。
4. **启用确认框**：已在 Core `0c7fee0` 上确认，安装与启用确认框只列出权限，不显示 `description`；安装时“同时启用”默认勾选。所以许可要求现在只在插件窗口、README 与骨骼查看器中可见，要靠 R4（#5）放进启用路径。

5. **路径的基准**：`skeleton.images` 与 `skeleton.audio` 在真实导出中相对于什么位置？需要用一份真实导出确认，再决定是否报告为文件引用。
6. **4.2 之后的格式变化**：骨骼 JSON 的解析在 4.3 发布后重新核对（骨骼预览已经用 4.3 运行时）。

## 12. 二进制骨骼的缩略图与查看器（0.3.0 交付）

**决定**（2026-10-14）：

| 编号 | 决定                                                                                                        | 理由                                                                                   |
| ---- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| S1   | 只声明 **`skel`** 的缩略图与查看器，`companionFormats: atlas, png, jpg, jpeg`；`json` 等 Core（§5）         | `.skel` 只有 Spine 使用，不涉及 R1                                                     |
| S2   | 按同名约定读取图集：同一目录的 `<骨骼文件名>.atlas`，再读取它的贴图页。**不报告为引用**                     | 读取用 SDK 的 `readCompanion`，不需要 R2。报告规则与 D3 相同                           |
| S3   | 打包 spine-ts 的 **4.2 与 4.3** 两条版本线，先从文件头读出版本再选择，每个运行时是一个按需加载的分块        | 运行时只读取与自己主次版本相同的数据。4.3 是当前最新的编辑器版本，4.2 仍被大量项目使用 |
| S4   | 用 spine-webgl 自己画，不用官方 Web Player                                                                  | Web Player 通过地址加载资源并自带界面；插件只能通过 SDK 读取文件，界面要与 Vormio 一致 |
| S5   | 测试用的 `.skel` 由素材脚本生成（§6 的 `preview/`），测试中用两个运行时读取验证；官方示例与真实导出不进仓库 | 与 D6 相同                                                                             |

**实施要点**：

- `src/preview/figure.ts` 按 4.3 的类型写成，4.2 只替换初始姿势、插槽复位、按名称换皮肤、建贴图与绘制这五处调用（`src/preview/runtime-4.2.ts`）。
- 贴图页用图片元素，不用 ImageBitmap：4.3 运行时通过 WebGL 的解包设置预乘非预乘的贴图页，而 WebGL 对 ImageBitmap 忽略这个设置。
- 缩略图：初始姿势、默认皮肤（没有可见附件时用第一个有的皮肤），按可见范围取景，两倍大小绘制后缩小。读不到的贴图页让缩略图失败。
- 查看器：打开时播放第一段动画，与 Spine 自己的播放器相同；读不到的贴图页用透明像素代替并说明原因。
- 文件名编码移到 `shared/uri.ts`：图集的页面地址与骨骼的同名图集、贴图页地址都要编码 `%`、`?`、`#`。
- 公开的二进制格式说明还是 3.8 的布局，素材生成器只能按运行时的读取器写（§9）。

**验收**：Node 与 Chromium 测试见插件 README。还没有在 Vormio-Core 中以开发目录手工验收：启用确认框应列出“缩略图：atlas、skel”“查看器：atlas、skel”与配套格式；网格中 `.skel` 显示初始姿势；查看器切换皮肤、播放动画；没有同名图集时显示原因；原文件不变。真实导出（需要持有 Spine 的人提供）只在手工验收时临时使用。
