# 查看器定位子资源：Spine 骨骼、glTF 与 OBJ

状态：**已实现并在 Core 0.0.10 上手工验收**（2026-10-16；F1 至 F8 同日确认）。Spine 0.13.0、glTF 0.5.0、OBJ 0.4.0，结论写进了三个插件 README 的查看器一节。

实施时与草案的不同：

- 把 key 读回对象的规则用的都是分析器自己的代码：glTF 的 `analysis.ts` 多了 `readKey`（类别与名称与报告相同），对象由 GLTFLoader 的 `associations` 找到；OBJ 的 `ObjAnalysis` 多了监听顶点与面的 `ObjListener`；Spine 的 `analyzeSkeleton` 可以顺带给出每个 key 代表的东西（`SkeletonKey`），二进制骨骼用 `skeleton-binary.ts` 从查看器的运行时读出的数据写回 JSON 后得到同样的 key。
- F3：标记画在骨骼画面上方的一层 2D 画布上，不用 `ShapeRenderer`：六个运行时版本的绘制接口各不相同，2D 层只需要世界坐标。附件与插槽的轮廓取它现在绘制的区域四边形或网格三角形：把绘制顺序暂时缩成这一个插槽调用 `getBounds`，运行时留在工作数组里的就是它的世界顶点（4.3 的绘制顺序在 `drawOrder.appliedPose`）。包围盒、路径、点与裁剪附件不参与绘制，不画；附件没有显示在插槽上时写明，不替它换上。
- F5：OBJ 不能按“目标照常显示”：OBJLoader 的分组与报告不一致，查看器用分析器重新读一遍文件，把属于这个对象、组或材质的面做成一个琥珀色的网格叠在模型上，其余淡化。文件按需重新读取，不常驻内存。
- F2：定位结束于下一次定位、清除、F（三个查看器）、R（glTF 与 OBJ；骨骼查看器没有 R）与换文件。
- glTF：GLTFLoader 的 associations 只保留最后加载的场景；默认场景不是最后一个的多场景文件，节点与网格可能找不到，此时写“（画面中没有可以标出的部分）”。

**测试**：glTF 的 `render.spec.ts`（节点、网格、材质与切换变体后重新找、相机、动画、未知 key 与其他文件、清除、F、换文件）；OBJ 的 `render.spec.ts`（组、对象、材质，琥珀色与淡化，未知 key、MTL 的 key 与其他文件，清除与 R）；Spine 的 `preview.spec.ts`（皮肤、动画、另一个皮肤的附件、没有显示的附件、插槽、骨骼，叠加层上的标记，清除与 F，`.skel` 的 key）。`pnpm run lint`、`pnpm run typecheck` 与 `pnpm test`（Node 153 个通过、2 个跳过，Chromium 76 个）全部通过。

**构建**（SDK 0.0.10）：Spine 0.13.0 `c4802000025d5831807089d27d37d10512c096780b758fd8400ce4578861cade`，glTF 0.5.0 `b0fb87e25268c127ec5a4e013a527be5a1fefd24e18e0eafc259b4204bdcc8d4`，OBJ 0.4.0 `383420de09b3c3680dc487008c19ecf8e3c10e36f3da1581d5f9fdf9f4f5f29b`。

**手工验收**（2026-10-16，Core 0.0.10）：tag `v0.0.10` 的干净导出，脚本驱动（复用 Core 的 e2e 辅助函数，截取插件页面核对）；新资源库关联 `fixtures/spine/basic`、`fixtures/obj/basic` 与 `fixtures/gltf/variants` 的副本，三个插件用“安装插件包…”安装并启用。

- Spine：在检视栏的“组成”中点 `armored` 皮肤，骨骼查看器切到这个皮肤；点 armored 的链接网格附件 `cape（区域 cape-armored）`，查看器写“已定位：链接网格附件 cape（区域 cape-armored）”，琥珀色画出它的网格三角形，随 idle 动画移动；点骨骼后画出骨骼的线段。

**发现**：从图集区域或 MTL 材质的“被引用”跳回使用它的文件（`hero.json`、`table.obj`）时，宿主只打开文件，没有请查看器定位到引用它的那个子资源（附件、组）。SDK 的说明只承诺“跳到另一个文件的子资源”时定位，这里跳的是文件，所以不是宿主的错误；要让查看器标出引用者，需要宿主在这种跳转时也发定位请求（引用的 `from`），属于 Core 的能力，插件内不绕过。

**发布**：2026-10-16 从合并提交 `fc36e68` 发布到官方目录序号 8。

**未验证**：深色主题下标记的颜色；真实导出的大模型重新读文件的耗时；从官方目录实际安装。路线图“下一批（2026-10-16 排定）”的第 2 项。涉及 Spine 0.13.0（骨骼查看器）、glTF 0.5.0 与 OBJ 0.4.0，都只改查看器页面，声明不变，使用者不用重新启用；不需要新的宿主能力（SDK 0.0.10，`apiVersion: 5`），在 Core 0.0.10 验收并合并 0.11.0 之后实施。

## 1. 目标

Core 0.0.9 起，使用者在检视栏点选一个子资源，或从另一个文件的引用跳到这个文件的子资源时，宿主向查看器发定位请求（`viewer(show, { focus })`，key 是本插件的分析器给这个子资源的 key；语义以 SDK README 的 “Focusing a subresource” 为准）。现在只有 Spine 的图集查看器响应（[Spine 设计计划](spine.md) §16 K6：换页、放大、高亮区域），骨骼查看器（K7 留下的部分）、glTF 与 OBJ 的查看器都忽略请求，点了没有反应。这份计划让三个查看器都响应：能在画面上找到的就取景并高亮，能切换的就切换，找不到的说明一下。

## 2. 决定

| 编号 | 决定                                                                                                                                                                                                                                                                                                                                                                             | 理由                                                                                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1   | 三个查看器都实现 `focus`；认不出或当前画面里不存在的 key 忽略                                                                                                                                                                                                                                                                                                                    | 宿主只在查看器与分析来自同一构建时发请求，key 一定是自己报告的；SDK 说明宿主不等答复，找不到就忽略                                                         |
| F2   | 定位的结果保留到下一次定位、使用者按 F 或 R 重新取景或切换文件为止；底部说明栏写“已定位：<类别> <名称>”，带“清除”按钮去掉高亮                                                                                                                                                                                                                                                    | 宿主处理 Esc，插件收不到；高亮一直留着会妨碍查看                                                                                                           |
| F3   | Spine 骨骼查看器：皮肤 → 切换到这个皮肤；动画 → 选择并从头播放这段动画；附件 → 当前皮肤没有它时先切到它所在的皮肤（报告中附件的上级），再按附件的世界顶点画轮廓（区域、网格、链接网格、包围盒、路径、裁剪按顶点，点附件画十字），轮廓随动画更新；骨骼 → 画这根骨骼的线段（原点到 `length` 处）并标名称；插槽 → 高亮它当前的附件，没有附件时只写说明；约束与事件 → 只写说明，不画 | 运行时能算出附件与骨骼的世界坐标（`computeWorldVertices`、骨骼的世界变换），用 spine-webgl 的 `ShapeRenderer` 画线不需要贴图；约束与事件没有稳定的画面位置 |
| F4   | glTF 查看器：节点与网格 → 取景到它并高亮（目标照常显示，其余网格按 25% 不透明度显示）；材质 → 高亮使用它的全部图元；贴图 → 高亮使用它的材质的图元；相机 → 切换到这台相机（已有下拉）；动画 → 选择并播放（已有下拉）；场景 → 取景整个场景；图像、缓冲、蒙皮等 → 只写说明                                                                                                          | 不引入描边后期：淡化其余物体用现有材质的 `transparent` 与 `opacity` 即可，恢复时放回原材质                                                                 |
| F5   | OBJ 查看器：对象与组 → 取景到它并高亮（同 F4）；材质 → 高亮使用它的面；材质库 → 只写说明。查看器自己按行解析时记录每个面属于哪个对象与组，高亮按这份记录，不按 OBJLoader 的分组                                                                                                                                                                                                  | 分析器的 key 是按文件顺序的序号，OBJLoader 的分组规则未必与它一致，查看器要用同样的顺序                                                                    |
| F6   | 取景沿用各自的 `framing.ts`（glTF 与 OBJ 各一份副本，O6 的结论不变）；高亮代码同样各放一份，文件开头写明要保持一致                                                                                                                                                                                                                                                               | `shared/` 解析不到 `three`（[OBJ 设计计划](obj.md)开头）                                                                                                   |
| F7   | glTF 的变体切换与 Spine 的皮肤切换会重建材质或附件，重建后高亮按 key 重新找；定位请求只在就绪之后处理（SDK 已保证）                                                                                                                                                                                                                                                              | 高亮依附的对象可能被替换                                                                                                                                   |
| F8   | 版本：Spine 0.13.0（可与 0.12.0 合并发布）、glTF 0.5.0、OBJ 0.4.0                                                                                                                                                                                                                                                                                                                | 只改查看器页面                                                                                                                                             |

## 3. 实施要点

- 三个查看器都已用 `viewer(show, …)`，加 `focus` 回调。把 key 解析回对象的规则与各自分析器的 key 规则放在一处（Spine：`skeleton.ts` 的 `keyOf`；glTF：`analysis.ts`；OBJ：`obj-file.ts`），不在查看器里另写一份。
- Spine 骨骼查看器的高亮用运行时的 `ShapeRenderer`（各版本的 spine-webgl 都有），在骨骼画完之后画；3.7、3.8 的 classic 命名放进 `Differences`。
- glTF 与 OBJ 的淡化：遍历场景把其余网格换成克隆的材质（`transparent: true, opacity: 0.25, depthWrite: false`），清除时放回；取景复用 `frameModel` 的顶点取法，只取目标的网格。

## 4. 测试素材

## 5. 测试与验收

- Chromium 测试（替身宿主的 `onFocus`，K6 已有）：每个查看器对已知 key 定位后状态或画面有变化（选中的皮肤与动画、相机位置、高亮像素），未知 key 与其他文件的 key 不变，切换文件后旧 key 被丢弃，清除后画面恢复；像素比较沿用现有做法。
- 手工验收（Core 0.0.10）：检视栏点选各类子资源；从 `hero.atlas` 某个区域的被引用跳回 `hero.json` 的附件；从 `table.mtl` 的材质的被引用跳回 `table.obj`；深色主题下高亮颜色可见；原文件不变。记录 Core 版本与未覆盖的部分。
