# glTF 查看器：动画、变体与相机

状态：**0.3.0 与 0.4.0 已实现**（2026-10-15），结论写进了[插件 README](../../plugins/gltf/README.md)，待手工验收。两个版本都只改查看器，不需要新的 SDK 或宿主能力（SDK 0.0.7，`apiVersion: 3`）。

0.3.0 实施时与草案的不同：

- 动画名称取自文件（`animations[].name`），没有名称时写成“动画 N”；GLTFLoader 自己的默认名（`animation_N`）不显示。
- G5 的“当前姿态”不需要单独计算蒙皮后的包围盒：three.js 的 `getVertexPosition` 已经应用蒙皮与变形目标，取景用的顶点直接按当前姿态取得；蒙皮网格的包围盒在每次测量前重新计算。
- 素材是一个 GLB（`fixtures/gltf/animated/robot.glb`），三种动画（节点、蒙皮、变形目标）放在同一个模型的两段动画中，第二段没有名称。
  0.4.0 实施时与草案的不同：

- G8 不需要写 GLTFLoader 插件：GLTFLoader 把不认识的扩展原样放进结果与每个图元网格的 `userData.gltfExtensions`，材质可以随时用 `parser.getDependency('material', i)` 加载，再用 `parser.assignFinalMaterial` 做与默认材质相同的调整，three.js 自己的变体示例就是这样切换的。变体的材质在第一次选择时才加载，随模型一起释放；它的贴图读不到时同样列出。
- G9：只列出默认场景中的相机（遍历场景，而不是 `gltf.cameras`：同一个相机被多个节点使用时 GLTFLoader 会克隆）。文件的 `aspectRatio` 不使用，宽度随查看区，避免拉伸；离开文件相机时，自由视角的目标点放在模型中心的深度（至少是模型半个对角线）。
- 拖动后马上按 R 时，OrbitControls 的阻尼惯性还会继续转动一小段，这是以前就有的行为，测试等画面静止后再按。
- 素材 `fixtures/gltf/variants/showroom.glb` 同时覆盖变体与两种相机。

- 顺带修了一个不稳定的渲染测试：`crate` 的缓冲区与贴图同时读取，顺序不固定。

## 1. 目标

插件 README 的“不支持的情况”中有三项是查看器自己的限制，与宿主无关：

- 动画不播放，显示静止姿态；蒙皮按绑定姿态、变形目标按基础形状显示。
- 文件中的相机不使用。
- `KHR_materials_variants` 只显示默认材质。

这份计划去掉这三项。缩略图与分析器不变：缩略图仍是静止姿态，分析器已经列出动画、相机与变体材质。

## 2. 决定

| 编号 | 决定                                                                                                                     | 理由                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| G1   | 0.3.0 只做动画，0.4.0 做变体与相机                                                                                       | 动画改动查看器的绘制循环与取景，单独验收；变体与相机是在它之上的两个开关                                        |
| G2   | 打开时**自动播放第一段动画**，循环播放；系统设置了“减少动态效果”（`prefers-reduced-motion`）时停在第一帧                 | 与 Spine 骨骼查看器和 Spine 自己的播放器一致；尊重系统设置                                                      |
| G3   | 底部工具栏加：动画片段下拉、播放/暂停、进度条（可拖动）、当前时间与总时长。没有动画的文件不显示这些控件                  | 只读查看所需的最少控件，不做速度、混合、多片段同时播放                                                          |
| G4   | 就绪之前不依赖动画帧：先把第一段动画放到第 0 秒并绘制，再报告就绪；播放从显示后的第一帧开始                              | 宿主在报告就绪之前隐藏页面，`requestAnimationFrame` 不会执行（[开发说明](../development.md)的“替身宿主”）       |
| G5   | 取景按打开时的姿态（第一段动画第 0 秒），播放中不自动重新取景；`F` 按当前姿态重新取景                                    | 预先采样所有片段的包围盒对大模型太慢；位移较大的动画由使用者按 `F`                                              |
| G6   | 每帧的时间增量上限 0.1 秒；页面隐藏时停止绘制循环                                                                        | 切换文件或窗口后回来不跳帧；不在看不见时占用 GPU                                                                |
| G7   | 键盘：空格播放/暂停；`F`、`R` 保持原样。空格是否与宿主快捷键冲突要在手工验收中确认                                       | 查看器已用 `F`、`R`，宿主的 `Esc` 返回网格                                                                      |
| G8   | 0.4.0 变体：自写 `GLTFLoader` 插件读取 `KHR_materials_variants`，变体下拉切换材质，默认是文件的默认材质。不引入第三方包  | three.js 0.186 本身不实现这个扩展，只在注释中指向外部仓库；读取映射约百行，自写比多一个依赖与它的许可说明更简单 |
| G9   | 0.4.0 相机：视角下拉列出“自由视角”与文件中的相机；选文件相机时按它的投影与位置绘制，拖动即回到自由视角（从那个位置开始） | 只读查看文件作者给的视角，不让文件相机变成可编辑状态                                                            |
| G10  | 声明的格式、配套格式与扩展点都不变，使用者不用重新启用；0.3.0 与 0.4.0 都是 `apiVersion: 3`                              | 只改查看器页面                                                                                                  |

## 3. 实施要点

- `model.ts`：`Model` 增加 `animations`（`AnimationClip[]`，来自 `gltf.animations`）与 0.4.0 的 `variants`、`cameras`。`dispose` 同时停止并释放 `AnimationMixer`。
- `viewer.ts`：现在的绘制循环只在相机移动后绘制（`dirty`）；播放时每帧更新 `AnimationMixer` 并绘制，暂停时回到按需绘制。切换文件时先停止上一个模型的混合器。
- 蒙皮网格的包围盒：`frameModel` 现在用顶点世界坐标（`worldPositions`）取景，没有考虑蒙皮。G5 的“当前姿态”要用蒙皮后的位置（three.js 的 `SkinnedMesh.computeBoundingBox` 或逐顶点 `applyBoneTransform`），大模型上的耗时要测量，超过阈值时退回包围盒。
- `KHR_animation_pointer`：three.js 0.186 不实现，含这个扩展的动画按 GLTFLoader 能读出的部分播放；它若是必需扩展，现有逻辑已拒绝显示。README 写明。
- 界面文字与现有查看器一样用中文；控件沿用 `viewer.css` 的样式，深色主题一起检查。

## 4. 测试素材

`scripts/fixtures/gltf.ts`（用已有的 `@gltf-transform/core`）生成 `fixtures/gltf/animated/`：

- 一个带两段动画的模型：节点的平移、旋转、缩放；一个蒙皮网格（两根关节）；一个变形目标的权重动画。
- 一个没有动画的模型继续用现有素材。
- 0.4.0 加入：带两个变体的模型（`KHR_materials_variants`），以及带透视与正交相机各一个的模型。

## 5. 测试与验收

- **Node 测试**：动画片段的列出、时长与名称（没有名称时“动画 N”）；变体映射的读取（0.4.0）。
- **Chromium 测试**（替身宿主）：
  - 就绪之前没有动画帧也能报告就绪，画面是第一帧（G4）。
  - 显示后画面随时间变化；暂停后不再变化；拖动进度条到同一时间得到同样的画面（像素比较）。
  - 切换片段、切换到没有动画的文件后控件隐藏；`prefers-reduced-motion` 时停在第一帧。
  - 0.4.0：切换变体后颜色变化；选文件相机后画面与按相机参数绘制的参考相同。
- **手工验收**：在当时最新的 Core 发布版本上加载开发目录（或安装打包的 `.vormioplugin`）：播放、暂停、拖动、切换片段，空格不与宿主冲突（G7），切换文件与返回网格后没有残留的播放，深色主题；原文件不变。记录 Core 版本与未覆盖的部分。

**手工验收**（2026-10-15，Core 0.0.8，glTF 0.4.0；0.3.0 不单独发布，代码并入 0.4.0）：脚本驱动（Playwright 的 Electron 驱动，临时用户数据目录，不连官方目录，不模拟配色），Core 0.0.8 是 tag `v0.0.8` 的干净导出（`pnpm install --frozen-lockfile` 与 `pnpm run build`，未打包启动）。三个插件是本分支 `pnpm run package spine gltf obj` 的包（Spine 0.9.0 `d0aaceae…`，glTF 0.4.0 `48851a97…`，OBJ 0.1.0 `06889bab…`），在插件窗口用“安装插件包…”安装并启用。新资源库关联 `fixtures/spine` 的 `basic`、`preview`，`fixtures/gltf` 的 `animated`、`variants`、`props` 与整个 `fixtures/obj` 的副本，共 74 个文件；全程原文件的内容与修改时间不变。

- `animated/robot.glb` 有缩略图；查看器“48 个三角形 · 2 段动画”，打开后在播放（时钟从 0.09 秒往前走）。通过宿主向插件页面发送空格键：暂停在 0.63 秒，之后时钟不再变化，查看模式没有退出（G7：空格不与宿主冲突）。
- `variants/showroom.glb` 列出“默认材质、Red、Blue”与“自由视角、Top、Side”；选 Blue 与 Side 后的截图是蓝色立方体，黄色小立方体挡在正中。
- 深色主题下 `robot.glb` 的查看器背景是深色。
- 未验证：拖动进度条与切换片段只在渲染测试中验证；没有用真实的外部模型。
