# 插件规划

本项目是 Vormio-Core 的下游：只有当发布的 SDK 提供了对应扩展点（Core 的正式版本，或 Core 为某个 issue 发布的预发布版）时，才开始相应的插件能力。宿主缺少的能力在 `Vormio/Vormio-Core` 提 issue，这里只记录 issue 号与解决它的 Core 版本。此后的手工验收记录 Core 的发布版本，不记录 Core 提交；下表中更早的记录保留原样。

Spine 的设计与后续版本见 [设计计划](plans/spine.md)。

**官方插件目录**（Core 0.0.5 起）：受邀测试者从 Vormio 的插件窗口安装、更新与回滚已经验收的官方插件。2026-10-14 第一次发布（序号 1）：glTF 0.2.0 与 Spine 0.2.0，来自 `982215d`（合并前是 `8eb019b`，内容相同）；当时本仓库还在用 SDK 0.0.3，目录由 Core 构建的 SDK 签名。换用 SDK 0.0.5 之后，发布配置 `release.json` 与命令 `pnpm run catalog` 都在本仓库，见[开发说明](development.md#发布官方目录)；域名、上传凭据与签名私钥不进仓库。

分支 `r4-agreement-candidates`（本分支）用 SDK 预发布版 0.0.10-rc.1 试用 Vormio/Vormio-Core#5（R4）与 #9（R3b）：Spine 0.11.0-r4.1、glTF 0.4.2-r4.1 与 OBJ 0.3.0-r4.1（`apiVersion: 5`），只交给 Core，不发布；Core 0.0.10 发布后换成正式版 SDK，去掉预发布标识，在 Core 0.0.10 上手工验收后合并。master 上现在的插件是 `apiVersion: 4`，给 Core 0.0.9 起的宿主：Spine 0.10.0、glTF 0.4.1 与 OBJ 0.2.0 已在 Core 0.0.9 上手工验收（2026-10-15）。`apiVersion: 3` 的 glTF 0.4.0、Spine 0.9.0 与 OBJ 0.1.0 已在 Core 0.0.8 上手工验收，之前的 glTF 0.2.3 与 Spine 0.8.0 已在 Core 0.0.7 上手工验收，都还没有进目录；`release.json` 已加入 OBJ。`pnpm run catalog` 只从当前提交发布当前 `apiVersion` 的版本，其他 `apiVersion` 只保留上一份目录中已有的发布，所以从合并后的提交发布时，`apiVersion: 3` 的版本不会进目录，Core 0.0.7 与 0.0.8 的宿主仍只看到上一份目录给它们的内容（没有）；要让它们也能安装，先从合并前的 master（`f9b1732`）发布一次（序号 3），再从合并后的提交发布（序号 4）。待决定。目录中最新的是 `apiVersion: 2`（glTF 0.2.1、Spine 0.4.0），给 Core 0.0.6 的宿主。2026-10-14 第二次发布（序号 2），来自 `7ed6344`，同时列出两组发布：

- 给 Core 0.0.6 的 glTF 0.2.1 与 Spine 0.4.0（`apiVersion: 2`），都已在 Core 0.0.6（tag `v0.0.6`）上手工验收。
- 给 Core 0.0.5 的 glTF 0.2.0 与 Spine 0.2.0（`apiVersion: 1`），由 `pnpm run catalog` 从上一份目录保留，沿用已发布的包（见[开发说明](development.md#发布官方目录)）。

Spine 0.4.0 起包含 Spine Runtimes，每个使用者都需要自己的 Spine Editor 许可证。2026-10-14 决定在 R4（Vormio/Vormio-Core#5）之前上架：许可要求写在插件说明的第一句（插件窗口的目录卡片上可见）、插件 README 与骨骼查看器底部，安装与启用的确认框里还看不到，见 [Spine 设计计划](plans/spine.md)第 10 节问题 3。Spine 0.3.0（`apiVersion: 1`）没有在 Core 0.0.5 上验收，没有进目录；0.0.5 的宿主继续用 Spine 0.2.0。

glTF 是宿主组成与关系契约的第一个真实使用方。2026-10-15 决定第三种格式是 OBJ + MTL（见下一节与插件表），2026-10-16 决定第四种格式是 FBX（见下一节与 [FBX 设计计划](plans/fbx.md)）；其他格式（压缩纹理、PSD、音频、字体、Blender 等）仍按真实需求逐个加入，上一版插件实现可以参考，但不直接搬运。
