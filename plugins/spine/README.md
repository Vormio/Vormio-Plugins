# Spine 骨骼动画

插件 ID `vormio-plugins.spine`，版本 0.7.0。

- **骨骼（`.json` 与 `.skel`）**：缩略图显示初始姿势，查看器可以切换皮肤、播放动画。渲染使用 Esoteric Software 的官方运行时 spine-ts。骨骼 JSON 还有组成分析：骨骼、插槽、约束、皮肤、附件、事件与动画，以及它们之间的引用。
- **不是 Spine 骨骼的 JSON**（`package.json`、配置、数据表等）：插件回答“不适用”，宿主照常显示类型图标与内置文本预览，没有组成区，也不记为失败。
- **纹理图集（`.atlas`，Spine 与 libGDX）**：缩略图显示第一页贴图，查看器在贴图页上画出区域框，可以搜索和定位区域；组成分析列出页面与区域，以及每个页面引用的贴图文件。

> **许可要求**：插件包含 Spine Runtimes，按 Spine Runtimes 许可协议分发，**每个使用者都需要自己的 Spine Editor 许可证**，只用图集查看与组成分析也一样：许可协议约束的是包含运行时的整个插件。分发方不持有 Spine Editor 许可证；插件无法核实使用者是否持有。每个运行时的协议原文随插件包附在 `licenses/SPINE-RUNTIMES-<版本>.txt`（3.7、3.8、4.0 与 4.1 带的是 2019 年版，4.2 与 4.3 带的是 2025 年版，条款相同）。

- **宿主**：Vormio-Core 0.0.6 起（插件契约 `apiVersion: 2`：分析器、缩略图与查看器可以按内容回答“不适用”）。宿主只加载与自己契约版本相同的插件；0.3.0 及更早的版本是 `apiVersion: 1`，给 Core 0.0.3 至 0.0.5。SDK 使用 [`vendor/`](../../vendor/README.md) 中固定的 0.0.6 打包产物。
- **不修改任何文件**：骨骼的缩略图与查看器读取骨骼、同一目录中的同名图集与图集的贴图页；图集的缩略图与查看器读取图集与它的 PNG、JPEG 贴图页；两个分析器只读取文件本身。
- 从 0.4.0 至 0.6.0 升级不需要重新启用：0.5.0 加入 3.7 骨骼 JSON 的预览，0.6.0 加入 3.7 二进制骨骼的预览，0.7.0 加入 3.7 骨骼 JSON 的组成分析，声明的格式与配套格式都没有变化。从 0.3.0 升级时为 `json` 新增了缩略图、查看器与分析器，需要在资源库中重新启用；Core 0.0.6 的资源库（格式 6）本身也要新建。从 0.2.0 升级时新增了骨骼的缩略图与查看器，许可要求也从那个版本开始；从 0.1.0 升级时新增了图集的缩略图与查看器。
- 设计与后续版本见 [设计计划](../../docs/plans/spine.md)。

## 支持的格式与版本

| 文件     | 版本                                                                                                                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.json`  | Spine 骨骼 JSON。缩略图与查看器：Spine 3.7、3.8 与 4.0 至 4.3，与二进制骨骼用同样的运行时；图集是同一目录中同名的 `.atlas`（`hero.json` → `hero.atlas`）。组成分析：Spine 3.7 至 4.2，更新的版本照常分析并附警告。其他 JSON 回答“不适用”（见下） |
| `.skel`  | Spine 3.7、3.8 与 4.0 至 4.3 导出的二进制骨骼，3.8 至 4.3 分别由同一主次版本的 spine-ts 读取，3.7 由插件移植的读取器读取（见下）；图集是同一目录中同名的 `.atlas`（`hero.skel` → `hero.atlas`）。3.7 与 3.8 的图集用 3.x 写法                    |
| `.atlas` | Spine 4.x 的写法（区域用 `bounds`、`offsets`，页面可有 `pma`、`scale`）与 Spine 3.x / libGDX 的写法（`xy`、`size`、`orig`、`offset`）                                                                                                            |

运行时只读取与自己主次版本相同的数据，所以插件先读出骨骼的版本（二进制骨骼在文件头，JSON 在 `skeleton.spine`），再加载对应的运行时；每个运行时各是一个分块，只在显示这个版本的骨骼时加载，图集的页面不加载运行时。其他版本（例如 3.6、5.0）显示原因，例如“Spine 5.0.00 的数据：插件只包含这些版本的运行时：3.7、3.8、4.0、4.1、4.2、4.3。”

3.7 的官方 Web 运行时（spine-ts 3.7）没有二进制读取器（`SkeletonBinary` 从 3.8 起才有）。插件按 spine-libgdx 3.7 的 `SkeletonBinary` 移植了一个（`src/preview/binary-3.7.ts`），把 3.7 的 `.skel` 读成 spine-ts 3.7 的数据类，之后与 3.7 的骨骼 JSON 一样由 spine-ts 3.7 绘制。它在 Spine 官方的 20 个 3.7 示例骨骼上与 spine-ts 3.7 的 `SkeletonJson` 读出相同的数据（见下面的测试）。3.7 与 3.8 的运行时不在 npm 上，是官方仓库中预先构建的脚本，都定义全局变量 `spine`；插件一次只加载一个，加载前清空这个全局变量，两个版本各用自己的类。

3.7 与 3.8 的图集不记录贴图页是否预乘透明度（4.0 起的 `pma`），插件与 Spine 自己的 3.7、3.8 播放器一样按预乘绘制。用不预乘的贴图导出的 3.7、3.8 骨骼，半透明的边缘会偏暗。

图集文本按 UTF-8 读取，可以有 BOM，换行可以是 LF 或 CRLF。

### 哪些 JSON 是 Spine 骨骼

宿主只按扩展名选择插件，库中每个 JSON 文件都会交给这个插件。识别条件是：内容是 JSON（可以有 BOM），顶层是对象，`skeleton` 是对象并且有字符串 `spine`（导出它的编辑器版本），还有 `bones` 数组。不满足时，缩略图、查看器与分析器都回答“不适用”，宿主改用下一个插件或内置预览，并且记住这个回答：同一版本的文件不再询问，直到文件变化或插件代码变化。

- 只依据文件本身判断，判断之前不读取图集或贴图页。
- 判断要读取并解析整个文件。Spine 编辑器把 `skeleton` 写在最前面，但其他工具重新写出的 JSON 不一定，只看文件开头会把这样的骨骼判为不适用。查看器第一次打开普通 JSON 时，内置文本预览要等这次判断，等待时间见[验收记录](#验收记录)。
- 是 Spine 骨骼、但插件处理不了的，照常说明原因，不回答“不适用”：例如 Spine 3.6 及更早的骨骼分析失败，没有对应运行时的版本与找不到同名图集时缩略图与查看器失败。

## 能力

### 骨骼

JSON 骨骼与二进制骨骼的缩略图、查看器相同。

**缩略图**：初始姿势，默认皮肤；默认皮肤在初始姿势下没有可见附件时，用第一个有可见附件的皮肤。按可见部分的范围取景，留出很小的边距，最长边是宿主给出的大小（目前 320 px），背景透明。物理约束不模拟。

**查看器**：

- 打开时播放第一段动画并循环，与 Spine 自己的播放器相同；没有动画的骨骼显示初始姿势。
- 工具栏：皮肤（多于一个时显示）、动画（含“初始姿势”）、播放与暂停（空格）、循环、速度（0.25× 至 2×）、适应（F）。
- 拖动平移，滚轮以光标为中心缩放。取景包含所选动画整个过程中的范围；切换皮肤或动画时重新取景，除非已经手动平移或缩放过。
- 底部：Spine 版本、骨骼与插槽数量、当前动画的时间，以及许可说明。
- 读不到的贴图页不中止显示：用到它的附件不画，左上角说明原因，例如“贴图页无法读取，用到它的附件不显示：torn.png（文件不存在）”。
- 浅色与深色主题跟随系统；换文件时释放上一份骨骼的贴图。

**失败的原因**（缩略图失败时宿主显示类型图标与原因；查看器向宿主报告）：

- 找不到同名图集，例如“找不到同名图集 orphan.atlas（文件不存在）”。
- 贴图页读不到（只有缩略图失败，查看器照常显示）。
- 二进制骨骼的文件开头没有 Spine 版本，或版本没有对应的运行时（JSON 骨骼也一样）。
- 运行时无法读取数据，例如文件被截断：“Spine 运行时无法读取这个骨骼：…”，后半句是运行时的原文。
- 初始姿势下没有可见的附件（只有缩略图失败）。

**骨骼 JSON 的组成分析**：只读取骨骼本身，结果显示在详情栏的“组成”区。解析不使用运行时，支持 Spine 3.7 至 4.2 的 JSON。3.7 的皮肤是以名称为键的对象（3.8 起是数组），没有专属的骨骼与约束；路径约束的时间轴叫 `paths`（3.8 起是 `path`）。

- **子资源**：骨骼（按父骨骼显示层级）、插槽、IK 约束、变换约束、路径约束、物理约束（4.2）、皮肤、附件（上级为皮肤，类别细分为区域、网格、链接网格、包围盒、路径、点、裁剪附件）、事件、动画。附件名称是附件键；查找区域用的名字（`path` 或 `name`）不同时写成“head（区域 head-front）”，序列附件写成“head-blink（区域 head-blink，3 帧）”。事件有音频时写成“footstep（音频 footstep.wav）”。
- **内部引用**：
  - 插槽 → 所在骨骼、初始附件（默认皮肤中的）。
  - 约束 → 约束骨骼、约束目标（路径约束的目标是插槽）。
  - 皮肤 → 皮肤专属的骨骼与约束。
  - 附件 → 所在插槽；链接网格 → 父网格（可以在其他皮肤）；裁剪附件 → 结束插槽。
  - 动画 → 骨骼、插槽、约束、事件与附件。附件来自 3.7 至 4.0 的 `deform` 时间轴，或 4.1 起的 `attachments` 时间轴；`drawOrder` 中的插槽也算。
  - 同一对象之间同一角色的引用只报告一次。证据是 JSON 指针；3.7 的附件在 `/skins/<皮肤名>/<插槽>/<附件>`，3.8 起在 `/skins/<序号>/attachments/<插槽>/<附件>`。
- **文件引用**：没有。同名图集是约定，文件中没有地址；`skeleton.images`、`skeleton.audio` 与事件音频的路径基准还没有用真实导出确认。
- **诊断**：引用的名称不存在（引用略去）、同名对象（按名称引用时只会找到第一个）、骨骼层级成环（断开一处）、无法识别的附件类型、结构不对的部分（报告标为部分完成）、比 4.2 新的版本。
- **失败**：3.6 及更早的版本；`skins` 的写法与版本不符的文件（3.8 起写成对象，或 3.7 写成数组），因为每个版本的运行时只读取自己的写法。
- **上限**：超出时按附件、动画、物理/路径/变换/IK 约束、事件、皮肤、插槽、骨骼的顺序，从最后一个开始略去。

### 图集

**缩略图**：第一张能读到的贴图页，按比例缩放到宿主给出的最长边（目前 320 px），背景透明。放大的小贴图保持像素清晰，缩小的平滑处理。前面的页面读不到时用后面的；所有页面都读不到时缩略图失败，宿主显示类型图标，并说明原因，例如“贴图页都无法显示：absent.png（文件不存在）”。

**查看器**：在贴图页上画出区域框，右侧列出区域。

- 拖动平移，滚轮以光标为中心缩放；“适应”（F）让整页回到视野中；“区域框”（B）显示或隐藏区域框。
- 悬停或点击区域显示它的名称、旋转前的尺寸、在页面上的位置与旋转角度；双击放大到这个区域。旋转 90° 的区域在页面上占用的宽高互换，区域框按实际占用画出。
- 区域列表可以按名称搜索（最多列出 1,000 个，其余可以搜索到）；点击区域会切到它所在的页面，放大并高亮。多页图集可以在工具栏选择页面，页面贴图在第一次显示时才读取。
- 贴图页读不到时仍显示区域框与页面大小（来自 `size`，没有时按区域的范围），并在左上角说明原因，例如“贴图页无法显示，只显示区域框：absent.png（文件不存在）”。
- 浅色与深色主题跟随系统；查看区较窄时隐藏区域列表。
- 换文件时释放上一份图集的贴图；不是图集的文本向宿主报告原因。

**组成分析**：宿主在后台调用分析器，结果显示在详情栏的“组成”区与贴图文件的“被引用”区。

- **子资源**：

  | 类别 | `key`            | 名称                                          | 上级     |
  | ---- | ---------------- | --------------------------------------------- | -------- |
  | 页面 | `pages/<序号>`   | 页面行写的图片文件名，原样显示                | —        |
  | 区域 | `regions/<序号>` | 区域名；`index` 不小于 0 时写成“名称（帧 N）” | 所在页面 |

- **文件引用**：每个页面引用它的图片，角色“贴图页”，证据为“第 N 行”。由宿主相对图集文件解析，可以带子目录与 `../`。图集里写的是文件名而不是 URI，所以文件名中的 `%`、`?`、`#` 会编码成 `%25`、`%3F`、`%23` 后报告，宿主解码后得到原来的文件名；其他字符（包括空格）原样报告。
- **诊断**：
  - 同一图集中名称与 `index` 都相同的区域：警告。Spine 按名称在整个图集中查找区域，只会用到第一个。
  - 没有位置（`bounds` 或 `xy`）的区域、数字个数或格式不对的字段：警告。
  - 无法识别的页面字段，以及第一个页面之前的字段：信息。区域中的其他字段是 Spine 的“名称/值”附加数据，不报告。
  - 超过 2,048 个字符的页面文件名：警告，这个页面不报告引用。
- **上限**：子资源超过 10,000 个或报告超过 4 MiB 时，保留全部页面与页面引用，从最后的区域开始略去，报告标为部分完成并附说明。名称去掉控制字符，按 200 个字符截断。
- **失败**：
  - 不是图集文本，即页面名之后不是页面字段，例如“不是 Spine 或 libGDX 图集：第 1 行的页面名后面应当是页面字段（例如 size: 1024, 512）。”
  - 没有任何页面。
  - 文件读不到或已经变化。

分析器不声明 `companionFormats`，因为它从不读取配套文件。图集的三个页面打包后共约 20 KB，不加载 Spine 运行时。

## 声明的权限

- 骨骼的缩略图与查看器（`skeleton`）：`formats: json, skel`，`companionFormats: atlas, png, jpg, jpeg`。
- 图集的缩略图与查看器（`atlas`）：`formats: atlas`，`companionFormats: png, jpg, jpeg`（Spine 打包器输出的贴图页格式）。
- 分析器：`atlas` 读 `formats: atlas`，`skeleton` 读 `formats: json`，都没有配套格式，共用一个页面。

增减其中任何一项都会改变权限，用户需要重新启用。

## 不支持的情况

- 二进制 `.skel` 的组成分析。
- Spine 4.3 骨骼 JSON 的组成分析按 4.2 的结构读取并附警告：4.3 把各种约束改写在一个 `constraints` 列表中，这些约束不会列出（设计计划 §10 问题 6）。缩略图与查看器由 4.3 运行时读取，不受影响。
- 骨骼预览只按同名约定查找图集：图集另起名字、多个骨骼共用一个图集时找不到。
- 3.7 之前与 4.3 之后的骨骼的预览（JSON 与二进制都是）。3.6 及更早的骨骼 JSON 也没有组成分析：皮肤的写法与 3.7 相同，但手上没有官方样本可以核对；3.5、3.6 的运行时按 Spine Runtimes Software License v2.5 只允许个人或内部使用，不能随插件分发；更早的版本没有 spine-ts；5.0 还没有发布。较早版本的资产，可以用新版编辑器打开原工程重新导出。
- 插件把一个 Spine 骨骼判为“不适用”时（识别条件见上），宿主没有按钮重新询问；修改文件或更新插件后才会再问。
- 骨骼预览中的事件音频、调试绘制（骨骼、包围盒、路径）与按插槽的显示开关。
- 启用前确认许可：宿主还不支持（设计计划 §8 R4），要求写在插件说明、本文与骨骼查看器中。
- 骨骼与图集的同名配对（`hero.json` ↔ `hero.atlas`）不报告为引用：它是约定，文件中没有地址（设计计划 §8 R2）。
- 区域与使用它的附件之间的关系：目前的契约不能引用另一个文件中的子资源（设计计划 §8 R3）。
- PNG 与 JPEG 以外的贴图页（例如 WebP、KTX2）：宿主拒绝读取；图集查看器只显示区域框，骨骼按“读不到的贴图页”处理。
- 图集查看器不显示预乘 alpha（`pma`）的校正、去白边前的原始尺寸（`offsets`、`orig`）与九宫格（`split`、`pad`）。骨骼预览由运行时按 `pma` 绘制。

## 验收记录

**Core 0.0.6（`02188f0`，插件 0.4.0），2026-10-14**：Core 提交的干净导出，未打包构建，脚本驱动，临时用户数据目录与新资源库（格式 6），开发目录加载 `dist/spine` 与 `dist/gltf`。关联文件夹是 `fixtures/spine`、`fixtures/gltf` 的副本，加上 8 个普通 JSON（`package.json`、`tsconfig.json`、配置、数据表、本地化文本、不完整的 JSON、`skeleton` 不是骨骼的 JSON），之后再复制进 2,000 个普通 JSON。逐条结果、发现的宿主问题与未验证的项目见[设计计划](../../docs/plans/spine.md)第 13 节。

- 骨骼 JSON 有骨骼缩略图、插件查看器与组成；普通 JSON 显示类型图标与内置文本预览，没有组成区，网格中没有“分析失败”或“组成过期”。
- 只问一次：重新打开资源库不再询问；修改一个普通 JSON 只重新询问它；插件代码变化后全部重新询问。
- 第一次在查看模式打开普通 JSON：只显示加载状态，**约 150–180 ms** 后切到内置文本预览（4 个文件分别为 170、150、171、152 ms，骨骼旁的 `settings.json` 178 ms）；第二次直接显示，约 11 ms。
- 2,000 个普通 JSON：复制进去后约 9 s 开始询问，**约 12 s 全部回答“不适用”**（从开始复制算起 21 s）；期间切换文件夹 57–112 ms，插件页面没有重建。
- 验收发现宿主的两个缩略图问题（与“不适用”无关，详见设计计划第 13 节），Core 在 0.0.6 收尾时已经修复（`166562d`）：内容相同的两个骨骼共用一张缩略图，即使它们的同名图集不同；一个文件夹里连续 3 个骨骼缩略图失败时，宿主重建插件页面，同时在处理的另一个骨骼显示“缩略图生成失败：The plugin page closed”。

**Core 0.0.6（master `f5e985a`，插件 0.4.0 合并 3.8、4.0、4.1 预览之后），2026-10-14**：同样的方式快速复查 18 项，全部通过：五个版本（3.8、4.0 至 4.3）的 JSON 骨骼与二进制骨骼都有缩略图并在查看器中播放，骨骼 JSON 都有组成；普通 JSON 仍是类型图标与文本预览；Core 修复后，没有同名图集或缺贴图页的骨骼显示自己的失败原因；glTF 照常。
