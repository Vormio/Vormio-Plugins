# Spine 骨骼动画

插件 ID `vormio-plugins.spine`，版本 0.12.0。

- **骨骼（`.json` 与 `.skel`）**：缩略图显示初始姿势，查看器可以切换皮肤、播放动画。渲染使用 Esoteric Software 的官方运行时 spine-ts。两种骨骼都有组成分析：骨骼、插槽、约束、皮肤、附件、事件与动画，以及它们之间的引用；同名图集与附件使用的图集区域作为推断的引用列出。
- **不是 Spine 骨骼的 JSON**（`package.json`、配置、数据表等）：插件回答“不适用”，宿主照常显示类型图标与内置文本预览，没有组成区，也不记为失败。
- **纹理图集（`.atlas`，Spine 与 libGDX）**：缩略图显示第一页贴图，查看器在贴图页上画出区域框，可以搜索和定位区域，宿主也可以让它定位到某个区域；组成分析列出页面与区域（区域按名称作 key），以及每个页面引用的贴图文件。

> **许可要求**：插件包含 Spine Runtimes，按 Spine Runtimes 许可协议分发，**每个使用者都需要自己的 Spine Editor 许可证**，只用图集查看与组成分析也一样：许可协议约束的是包含运行时的整个插件。分发方不持有 Spine Editor 许可证；插件无法核实使用者是否持有。manifest 把协议声明为启用前需要同意的协议（`agreement`，标题“Spine Runtimes 许可协议”，全文 `licenses/SPINE-RUNTIMES.txt`，即 2025-04-05 版，它取代之前的版本）：在资源库中启用插件时宿主写明需要同意、提供全文，同意后才启用；宿主只记录使用者的选择，不核实任何内容。每个运行时自己带的协议原文仍随插件包附在 `licenses/SPINE-RUNTIMES-<版本>.txt`（3.7、3.8、4.0 与 4.1 带的是 2019 年版，4.2 与 4.3 带的是 2025 年版，条款相同）。

- **宿主**：Vormio-Core 0.0.10 起（插件契约 `apiVersion: 5`：manifest 可以声明启用前需要同意的协议；0.0.9 起的跨文件子资源引用与查看器定位、0.0.7 起的推断引用与 0.0.6 起的“不适用”照旧）。宿主只加载与自己契约版本相同的插件：0.10.0 是 `apiVersion: 4`，给 Core 0.0.9；0.8.0 与 0.9.0 是 `apiVersion: 3`，给 Core 0.0.7 与 0.0.8；0.4.0 是 `apiVersion: 2`，给 Core 0.0.6；0.3.0 及更早的版本是 `apiVersion: 1`，给 Core 0.0.3 至 0.0.5。SDK 使用 [`vendor/`](../../vendor/README.md) 中固定的 0.0.10 打包产物。
- **不修改任何文件**：骨骼的缩略图与查看器读取骨骼、同一目录中的同名图集与图集的贴图页；图集的缩略图与查看器读取图集与它的 PNG、JPEG 贴图页；两个分析器只读取文件本身。

- 设计与后续版本见 [设计计划](../../docs/plans/spine.md)。

## 支持的格式与版本

| 文件     | 版本                                                                                                                                                                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.json`  | Spine 骨骼 JSON。缩略图与查看器：Spine 3.7、3.8 与 4.0 至 4.3，与二进制骨骼用同样的运行时；图集是同一目录中同名的 `.atlas`（`hero.json` → `hero.atlas`）。组成分析：Spine 3.7 至 4.3，更新的版本照常分析并附警告。其他 JSON 回答“不适用”（见下）                        |
| `.skel`  | Spine 3.7、3.8 与 4.0 至 4.3 导出的二进制骨骼，3.8 至 4.3 分别由同一主次版本的 spine-ts 读取，3.7 由插件移植的读取器读取（见下）；图集是同一目录中同名的 `.atlas`（`hero.skel` → `hero.atlas`）。3.7 与 3.8 的图集用 3.x 写法。组成分析：同样的版本，由同样的运行时读取 |
| `.atlas` | Spine 4.x 的写法（区域用 `bounds`、`offsets`，页面可有 `pma`、`scale`）与 Spine 3.x / libGDX 的写法（`xy`、`size`、`orig`、`offset`）                                                                                                                                   |

运行时只读取与自己主次版本相同的数据，所以插件先读出骨骼的版本（二进制骨骼在文件头，JSON 在 `skeleton.spine`），再加载对应的运行时；每个运行时各是一个分块，只在显示这个版本的骨骼时加载，图集的页面不加载运行时。其他版本（例如 3.6、5.0）显示原因，例如“Spine 5.0.00 的数据：插件只包含这些版本的运行时：3.7、3.8、4.0、4.1、4.2、4.3。”

3.7 的官方 Web 运行时（spine-ts 3.7）没有二进制读取器（`SkeletonBinary` 从 3.8 起才有）。插件按 spine-libgdx 3.7 的 `SkeletonBinary` 移植了一个（`src/preview/binary-3.7.ts`），把 3.7 的 `.skel` 读成 spine-ts 3.7 的数据类，之后与 3.7 的骨骼 JSON 一样由 spine-ts 3.7 绘制。它在 Spine 官方的 20 个 3.7 示例骨骼上与 spine-ts 3.7 的 `SkeletonJson` 读出相同的数据（见下面的测试）。3.7 与 3.8 的运行时不在 npm 上，是官方仓库中预先构建的脚本，都定义全局变量 `spine`；插件一次只加载一个，加载前清空这个全局变量，两个版本各用自己的类。

3.7 与 3.8 的图集不记录贴图页是否预乘透明度（4.0 起的 `pma`），插件与 Spine 自己的 3.7、3.8 播放器一样按预乘绘制。用不预乘的贴图导出的 3.7、3.8 骨骼，半透明的边缘会偏暗。

图集文本按 UTF-8 读取，可以有 BOM，换行可以是 LF 或 CRLF。

### 哪些 JSON 是 Spine 骨骼

宿主只按扩展名选择插件，库中每个 JSON 文件都会交给这个插件。识别条件是：内容是 JSON（可以有 BOM），顶层是对象，`skeleton` 是对象并且有字符串 `spine`（导出它的编辑器版本），还有 `bones` 数组。不满足时，缩略图、查看器与分析器都回答“不适用”，宿主改用下一个插件或内置预览，并且记住这个回答：同一版本的文件不再询问，直到文件变化或插件代码变化。

- 只依据文件本身判断，判断之前不读取图集或贴图页。
- 判断要读取并解析整个文件。Spine 编辑器把 `skeleton` 写在最前面，但其他工具重新写出的 JSON 不一定，只看文件开头会把这样的骨骼判为不适用。查看器第一次打开普通 JSON 时，内置文本预览要等这次判断，等待时间见[验收记录](#验收记录)。
- 是 Spine 骨骼、但插件处理不了的，照常说明原因，不回答“不适用”：例如 Spine 3.6 及更早的骨骼分析失败，没有对应运行时的版本与找不到同名图集时缩略图与查看器失败。

## 能力

### 骨骼

JSON 骨骼与二进制骨骼的缩略图、查看器相同。

**缩略图**：初始姿势，默认皮肤；默认皮肤在初始姿势下没有可见附件时，用第一个有可见附件的皮肤。按可见部分的范围取景，留出很小的边距，最长边是宿主给出的大小（目前 320 px），背景透明。物理约束不模拟。

**查看器**：

- 打开时播放第一段动画并循环，与 Spine 自己的播放器相同；没有动画的骨骼显示初始姿势。
- 工具栏：皮肤（多于一个时显示）、动画（含“初始姿势”）、播放与暂停（空格）、循环、速度（0.25× 至 2×）、适应（F）。
- 拖动平移，滚轮以光标为中心缩放。取景包含所选动画整个过程中的范围；切换皮肤或动画时重新取景，除非已经手动平移或缩放过。
- 底部：Spine 版本、骨骼与插槽数量、当前动画的时间，以及许可说明。
- 读不到的贴图页不中止显示：用到它的附件不画，左上角说明原因，例如“贴图页无法读取，用到它的附件不显示：torn.png（文件不存在）”。
- 浅色与深色主题跟随系统；换文件时释放上一份骨骼的贴图。

**失败的原因**（缩略图失败时宿主显示类型图标与原因；查看器向宿主报告）：

- 找不到同名图集，例如“找不到同名图集 orphan.atlas（文件不存在）”。
- 贴图页读不到（只有缩略图失败，查看器照常显示）。
- 二进制骨骼的文件开头没有 Spine 版本，或版本没有对应的运行时（JSON 骨骼也一样）。
- 运行时无法读取数据，例如文件被截断：“Spine 运行时无法读取这个骨骼：…”，后半句是运行时的原文。
- 初始姿势下没有可见的附件（只有缩略图失败）。

**骨骼 JSON 的组成分析**：只读取骨骼本身，结果显示在详情栏的“组成”区。解析不使用运行时，支持 Spine 3.7 至 4.3 的 JSON。3.7 的皮肤是以名称为键的对象（3.8 起是数组），没有专属的骨骼与约束；路径约束的时间轴叫 `paths`（3.8 起是 `path`）。4.3 把所有约束写在一个 `constraints` 列表中，每项用 `type` 区分，并加入滑块约束；变换约束的目标骨骼叫 `source`，路径约束的插槽叫 `slot`，链接网格的父网格叫 `source`（父网格在别的插槽时用 `slot` 指明），绘制顺序可以按“文件夹”只重排其中的插槽（`drawOrderFolder`）。这些来自 spine-core 4.3 的读取器，测试用它核对。

- **子资源**：骨骼（按父骨骼显示层级）、插槽、IK 约束、变换约束、路径约束、物理约束（4.2）、滑块约束（4.3）、皮肤、附件（上级为皮肤，类别细分为区域、网格、链接网格、包围盒、路径、点、裁剪附件）、事件、动画。附件名称是附件键；查找区域用的名字（`path` 或 `name`）不同时写成“head（区域 head-front）”，序列附件写成“head-blink（区域 head-blink，3 帧）”。事件有音频时写成“footstep（音频 footstep.wav）”。
- **内部引用**：
  - 插槽 → 所在骨骼、初始附件（默认皮肤中的）。
  - 约束 → 约束骨骼、约束目标（路径约束的目标是插槽）；滑块约束 → 驱动它的骨骼（有时）与它播放的动画（角色“滑块动画”）。
  - 皮肤 → 皮肤专属的骨骼与约束。
  - 附件 → 所在插槽；链接网格 → 父网格（可以在其他皮肤）；裁剪附件 → 结束插槽。
  - 动画 → 骨骼、插槽、约束、事件与附件。附件来自 3.7 至 4.0 的 `deform` 时间轴，或 4.1 起的 `attachments` 时间轴；`drawOrder` 与 4.3 的 `drawOrderFolder` 中的插槽也算。
  - 同一对象之间同一角色的引用只报告一次。证据是 JSON 指针；3.7 的附件在 `/skins/<皮肤名>/<插槽>/<附件>`，3.8 起在 `/skins/<序号>/attachments/<插槽>/<附件>`；4.3 的约束在 `/constraints/<序号>`。
- **文件引用**：同名图集（`hero.json` → `hero.atlas`）与其中的区域，都作为推断的引用报告。图集的角色是“图集”，依据“与骨骼文件同名”。骨骼文件中没有图集的地址，Spine 按同名约定把两者配对。
  - 只在骨骼有从图集取图的附件（区域、网格、链接网格）时报告；只有包围盒、点、路径、裁剪附件的骨骼不需要图集。
  - 不检查图集是否存在，由宿主在查询时判断：找不到时显示“未找到”，不算缺失引用。地址与骨骼预览读取的相同，文件名中的 `%`、`?`、`#` 编码后报告。
  - 图集另起名字或多个骨骼共用一个图集时，名字不同的骨骼推断不到它（设计计划 §8）。
  - **图集区域**：每个区域、网格与链接网格附件再报告它使用的区域，从附件指向同名图集，`uriKey` 是图集分析器给这个区域的 key `region:<名称>`，角色“图集区域”，依据同样是“与骨骼文件同名”，证据是附件的 JSON 指针。名称是运行时查找区域用的名字：`path`，没有时是附件的 `name`，再没有时是附件键。4.1 起的序列附件每一帧一条，名称按运行时的规则是基础名称加帧号（从 `start` 起，默认 1，按 `digits` 补零），证据指向 `sequence`；4.0 及更早的运行时不读 `sequence`，只报告基础名称。不读取图集，也不检查区域是否存在：宿主在查询时按图集的报告判断，图集由同一个插件构建分析时才连上，找不到区域时显示“未找到”。测试让每个版本的运行时读取素材骨骼并记录它查找的区域名，与报告的 `uriKey` 逐一核对。
  - 名称长到 key 超过 200 个字符的区域不报告（图集中也没有这样的 key），图集本身照常报告。
  - `skeleton.images`、`skeleton.audio` 与事件音频的路径基准还没有用真实导出确认，不报告。
- **诊断**：引用的名称不存在（引用略去）、同名对象（按名称引用时只会找到第一个）、骨骼层级成环（断开一处）、无法识别的附件类型与约束类型、结构不对的部分（报告标为部分完成）、比 4.3 新的版本。
- **失败**：3.6 及更早的版本；`skins` 的写法与版本不符的文件（3.8 起写成对象，或 3.7 写成数组），因为每个版本的运行时只读取自己的写法；约束的写法与版本不符的文件同理（4.3 起写在 `constraints` 中，之前写在 `ik`、`transform`、`path`、`physics` 中）。
- **上限**：超出时按附件、动画、物理/路径/变换/IK 约束、事件、皮肤、插槽、骨骼的顺序，从最后一个开始略去（4.3 的滑块约束在物理约束之前略去）。图集区域的引用最多占报告大小（4 MiB）的一半，超出的部分不报告，报告标为部分完成并说明“附件使用的图集区域太多，只列出一部分”，附件本身照常列出；引用超过 50,000 条时同样只列出一部分，不会使分析失败。

**二进制骨骼的组成分析**：只读取骨骼本身。二进制的布局每个版本都不同，公开的说明只到 3.8，所以插件用预览所用的同一个运行时读取（3.7 用插件移植的读取器），用一份只有一个区域的替身图集代替真正的图集，附件照写出的样子读出，不读同名图集与贴图页。读出的数据按同一版本的骨骼 JSON 写回，再交给骨骼 JSON 的分析器，所以子资源、key、名称、内部引用、推断的同名图集与区域、诊断与上限都与上面相同。

- 引用没有证据：二进制文件没有 JSON 指针。
- 绘制顺序：运行时只保留每一帧完整的顺序，不知道文件里列出了哪些插槽。插件把没有列出的插槽看作保持原有顺序的那些（运行时就是这样填补的），报告最长递增序列以外的插槽；一个插槽前后交换的帧，两种看法都成立，报告的可能是另一个。
- 运行时读不了的文件（截断、损坏）分析失败，原因与缩略图相同：“Spine 运行时无法读取这个骨骼：…”。没有对应运行时的版本（例如 3.6、5.0）与文件开头没有 Spine 版本的文件同样失败；`.skel` 只有 Spine 使用，不回答“不适用”。
- 分析器页面遇到 `.skel` 时才加载这个版本的运行时（每个约 230 KB），骨骼 JSON 与图集不加载。

### 图集

**缩略图**：第一张能读到的贴图页，按比例缩放到宿主给出的最长边（目前 320 px），背景透明。放大的小贴图保持像素清晰，缩小的平滑处理。前面的页面读不到时用后面的；所有页面都读不到时缩略图失败，宿主显示类型图标，并说明原因，例如“贴图页都无法显示：absent.png（文件不存在）”。

**查看器**：在贴图页上画出区域框，右侧列出区域。

- 拖动平移，滚轮以光标为中心缩放；“适应”（F）让整页回到视野中；“区域框”（B）显示或隐藏区域框。
- 悬停或点击区域显示它的名称、旋转前的尺寸、在页面上的位置与旋转角度；双击放大到这个区域。旋转 90° 的区域在页面上占用的宽高互换，区域框按实际占用画出。
- 区域列表可以按名称搜索（最多列出 1,000 个，其余可以搜索到）；点击区域会切到它所在的页面，放大并高亮。多页图集可以在工具栏选择页面，页面贴图在第一次显示时才读取。
- **定位**：在检视栏选中图集的区域，或从骨骼的“图集区域”引用跳到图集时，宿主请查看器显示这个子资源（按组成分析的 key）：区域与点击列表一样切到它所在的页面，放大并在列表中高亮；搜索框隐藏了它时清空搜索。页面的 key 切到这一页。同一个 key 再次请求时再显示一次；图集中没有的 key 不处理。
- 贴图页读不到时仍显示区域框与页面大小（来自 `size`，没有时按区域的范围），并在左上角说明原因，例如“贴图页无法显示，只显示区域框：absent.png（文件不存在）”。
- 浅色与深色主题跟随系统；查看区较窄时隐藏区域列表。
- 换文件时释放上一份图集的贴图；不是图集的文本向宿主报告原因。

**组成分析**：宿主在后台调用分析器，结果显示在详情栏的“组成”区与贴图文件的“被引用”区。

- **子资源**：

  | 类别 | `key`                                | 名称                                          | 上级     |
  | ---- | ------------------------------------ | --------------------------------------------- | -------- |
  | 页面 | `pages/<序号>`                       | 页面行写的图片文件名，原样显示                | —        |
  | 区域 | `region:<名称>`，或 `regions/<序号>` | 区域名；`index` 不小于 0 时写成“名称（帧 N）” | 所在页面 |

  区域按名称作 key，骨骼的“图集区域”引用用它指向区域（`uriKey`），所以重新导出图集后 key 不变。只有 Spine 按名称找到的那个区域，即图集中这个名称的第一个区域，得到 `region:<名称>`（Spine 按名称查找时不看 `index`）；之后同名的区域（包括同名的其他帧）与名称长到 key 超过 200 个字符的区域用 `regions/<序号>`，序号是区域在整个图集中的位置。

- **文件引用**：每个页面引用它的图片，角色“贴图页”，证据为“第 N 行”。由宿主相对图集文件解析，可以带子目录与 `../`。图集里写的是文件名而不是 URI，所以文件名中的 `%`、`?`、`#` 会编码成 `%25`、`%3F`、`%23` 后报告，宿主解码后得到原来的文件名；其他字符（包括空格）原样报告。
- **诊断**：
  - 同一图集中名称与 `index` 都相同的区域：警告。Spine 按名称在整个图集中查找区域，只会用到第一个。
  - 没有位置（`bounds` 或 `xy`）的区域、数字个数或格式不对的字段：警告。
  - 无法识别的页面字段，以及第一个页面之前的字段：信息。区域中的其他字段是 Spine 的“名称/值”附加数据，不报告。
  - 超过 2,048 个字符的页面文件名：警告，这个页面不报告引用。
- **上限**：子资源超过 10,000 个或报告超过 4 MiB 时，保留全部页面与页面引用，从最后的区域开始略去，报告标为部分完成并附说明。名称去掉控制字符，按 200 个字符截断。
- **失败**：
  - 不是图集文本，即页面名之后不是页面字段，例如“不是 Spine 或 libGDX 图集：第 1 行的页面名后面应当是页面字段（例如 size: 1024, 512）。”
  - 没有任何页面。
  - 文件读不到或已经变化。

分析器不声明 `companionFormats`，因为它从不读取配套文件。图集的三个页面打包后共约 20 KB，不加载 Spine 运行时；分析器页面只在分析二进制骨骼时加载。

## 声明的权限

- 骨骼的缩略图与查看器（`skeleton`）：`formats: json, skel`，`companionFormats: atlas, png, jpg, jpeg`。
- 图集的缩略图与查看器（`atlas`）：`formats: atlas`，`companionFormats: png, jpg, jpeg`（Spine 打包器输出的贴图页格式）。
- 分析器：`atlas` 读 `formats: atlas`，`skeleton` 读 `formats: json, skel`（0.12.0 起加了 `skel`），都没有配套格式，共用一个页面。

增减其中任何一项都会改变权限，用户需要重新启用。

## 不支持的情况

- 骨骼预览只按同名约定查找图集：图集另起名字、多个骨骼共用一个图集时找不到。
- 3.7 之前与 4.3 之后的骨骼的预览（JSON 与二进制都是）。3.6 及更早的骨骼 JSON 也没有组成分析：皮肤的写法与 3.7 相同，但手上没有官方样本可以核对；3.5、3.6 的运行时按 Spine Runtimes Software License v2.5 只允许个人或内部使用，不能随插件分发；更早的版本没有 spine-ts；5.0 还没有发布。较早版本的资产，可以用新版编辑器打开原工程重新导出。
- 插件把一个 Spine 骨骼判为“不适用”时（识别条件见上），宿主没有按钮重新询问；修改文件或更新插件后才会再问。
- 骨骼预览中的事件音频、调试绘制（骨骼、包围盒、路径）与按插槽的显示开关。
- 确认、改指或否定推断的图集（人工关联）：宿主还不支持（设计计划 §8）。
- PNG 与 JPEG 以外的贴图页（例如 WebP、KTX2）：宿主拒绝读取；图集查看器只显示区域框，骨骼按“读不到的贴图页”处理。
- 图集查看器不显示预乘 alpha（`pma`）的校正、去白边前的原始尺寸（`offsets`、`orig`）与九宫格（`split`、`pad`）。骨骼预览由运行时按 `pma` 绘制。
