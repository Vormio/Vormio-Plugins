# OBJ 模型

插件 ID `vormio-plugins.obj`，版本 0.1.0。为 Wavefront OBJ 模型提供缩略图、只读三维查看器和组成分析，为 MTL 材质库提供组成分析。

- **宿主**：Vormio-Core 0.0.7 起（插件契约 `apiVersion: 3`）。“不适用”的回答要求 Core 0.0.6 起。SDK 使用 [`vendor/`](../../vendor/README.md) 中固定的 0.0.7 打包产物。
- **不修改任何文件**：只读取宿主绑定的文件，以及模型写出的、扩展名在声明范围内的材质库与贴图。
- 设计与后续版本见 [设计计划](../../docs/plans/obj.md)。

## 支持的格式与版本

| 文件   | 内容                                                                                                                 |
| ------ | -------------------------------------------------------------------------------------------------------------------- |
| `.obj` | Wavefront OBJ 文本：多边形面、线与点，对象（`o`）、组（`g`）、材质（`usemtl`）与材质库（`mtllib`）；顶点可以带颜色   |
| `.mtl` | Wavefront MTL 材质库：`newmtl` 定义的材质，颜色、光泽、透明度与贴图语句（含常见的 PBR 扩展 `Pr`、`Pm`、`map_Pr` 等） |

贴图格式：PNG、JPEG、TGA（three.js 的 TGALoader）、BMP（由 Chromium 解码）。

文件中的名称是文件路径，不是 URI：Windows 导出的 `\` 当作 `/`；`%`、`?`、`#` 编码后交给宿主，宿主还原成原文件名。以 `#` 开头的整行是注释（与 three.js 的读取器相同），行中的 `#` 是名称的一部分；以 `\` 结尾的行与下一行相连。

**不是 OBJ 的 `.obj`**：编译器也用 `.obj` 作目标文件的扩展名（MSVC 的 COFF、GCC 与 Clang 的 ELF）。文件开头 4 KB 中有 NUL 字节，或整个文件没有任何 OBJ 语句（`v`、`f`、`o`、`g`、`usemtl`、`mtllib` 等）时，缩略图、查看器与分析器都回答“不适用”：宿主显示类型图标、不显示组成，并且记住这个回答，同一版本的文件不再询问。判断只读文件本身，在读取任何配套文件之前。

## 能力

**缩略图**：在宿主的隐藏页面中用 WebGL 渲染整个模型，按顶点取景（顶点超过 100 万时按包围盒），透明背景，宿主给出的最长边（目前 320 px）。先以两倍尺寸渲染再缩小。材质库、贴图或材质读不到时，相应部分只用颜色显示，缩略图照常生成。灯光、环境与取景与 glTF 插件相同。

**查看器**：与缩略图相同的加载、光照与取景代码。

- 拖动旋转，滚轮缩放（向光标处缩放），右键或 Shift + 拖动平移；“适应”（F）、“重置视角”（R）。
- 底部显示三角形数与材质数。读不到的材质库与贴图在左上角列出路径与原因（例如“../materials/paint.mtl（文件不存在）”），材质库中找不到的材质写成“材质 Ghost（材质库中没有定义）”。
- 连续查看时复用同一页面，换文件前释放上一个模型。

**材质**：

- 先读出模型写出的全部材质库，每个相对模型文件；它们的贴图相对各自的材质库读取。three.js 的 OBJLoader 只记录最后一个材质库，所以插件自己找出所有 `mtllib`，按顺序读取；同名的材质以后面的材质库为准。
- 贴图语句的选项（`-s`、`-o`、`-bm`、`-clamp`、`-mm` 等）按格式规定的参数个数跳过，剩下的是文件名，可以含空格。MTLLoader 只认识 `-bm`、`-s`、`-o`，并且把其他选项当作文件名的一部分，所以插件把贴图语句改写成只带这三个选项、文件名已编码的形式再交给它（其余选项不生效）。
- 没有材质的部分是灰色；带顶点颜色的部分按顶点颜色显示。贴图读不到时材质保留自己的颜色，不画成黑色。

**组成分析**：宿主在后台调用分析器，结果显示在“组成”区与被引用文件的“被引用”区。分析只读文件本身：OBJ 按块读取并逐行统计，不构建几何体；MTL 读取整个文件。

- **OBJ 的子资源**：对象（`o`，名称附带面数，例如“Legs（24 个面）”；第一个 `o` 之前的面属于隐含的对象“默认”）、组（`g`，上级是所在对象；同一对象中同名的组算一个）、材质（`usemtl` 用到的名称，按第一次出现的顺序）。
- **OBJ 的引用**：每个 `mtllib` 文件名引用材质库，角色“材质库”，证据“第 N 行”；一行写了多个文件名时记一条信息（文件名中的空格无法写进 OBJ）。组（或没有组的对象）→ 它的面使用的材质，角色“使用材质”。
- **MTL 的子资源与引用**：每个 `newmtl` 一个材质；材质 → 贴图，角色是中文名（漫反射贴图、凹凸贴图、法线贴图、反射贴图（cube_top）等，未知的 `map_*` 写成“贴图（map_Xyz）”），证据“第 N 行”。
- **诊断**：面引用了不存在的顶点、贴图坐标或法线（统计次数与第一处的行号）、用了材质却没有材质库、自由曲线与曲面（不显示）、无法识别的语句（每种一次）；MTL 中重复的材质名、第一个 `newmtl` 之前的语句、没有文件名的贴图语句。
- **上限**：与 SDK 的 `reportLimits` 一致；超出时先保留材质库引用与材质，再按组、对象的顺序略去，报告标为部分完成。

## 声明的权限

缩略图与查看器声明 `formats: obj` 与 `companionFormats: mtl, png, jpg, jpeg, tga, bmp`。两个分析器分别声明 `obj` 与 `mtl`，不读取配套文件，不声明配套格式。增减其中任何一项都会改变权限指纹，使用者需要重新启用。

## 不支持的情况

- 自由曲线与曲面（`curv`、`surf` 等）：分析器记一条信息，查看器与缩略图不显示。
- `usemtl` 指向材质库中的哪一个材质：分析器只报告材质名与材质库文件，不连到 `.mtl` 报告中的材质，等 Vormio-Core 的跨文件子资源引用（Vormio/Vormio-Core#3）。
- DDS 等压缩纹理、未声明扩展名的贴图：宿主拒绝读取，查看器列出“插件不读取这种类型的文件”。分析器照常报告这些引用。
- 绝对路径（例如 `C:\textures\wood.png`）与 `http(s):` 地址：插件不能读取关联文件夹以外的文件；分析器原样报告，由宿主归类。
- MTLLoader 不支持的材质效果不显示：反射贴图（`refl`）、`-clamp`、`-mm` 等贴图选项、`illum` 光照模型与 PBR 参数；材质类型是 Phong。
- 非 UTF-8 编码的名称（例如 GBK）按 UTF-8 解码，可能显示乱码。
- 很大的模型：114 MB、196 万个顶点与 196 万个四边形的 OBJ 在开发机上分析约 1.7 秒、缩略图约 6 秒、查看器约 5 秒就绪（宿主时限：缩略图与分析 30 秒，查看器 15 秒）；解析时内存占用较大。插件没有自己的大小上限。

## 构建、开发与测试

在仓库根目录运行（准备工作见仓库 README）：

```bash
pnpm run build obj
```

输出到 `dist/obj/`，可以作为开发目录加载。

```bash
pnpm run package obj
```

生成 `artifacts/vormio-plugins.obj-0.1.0.vormioplugin`。

测试（`pnpm test` 会先构建）：

| 文件                     | 内容                                                                                                                                                                                                                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/analysis.test.ts` | OBJ 与 MTL 的组成报告：对象、组、材质、材质库与贴图引用、证据行号；名称编码；面索引与其他诊断；分块读取、CRLF、续行与注释；不是 OBJ 的文本与二进制；贴图选项的参数个数；交给 MTLLoader 的改写；超上限时部分报告。每份报告都用 SDK 的 `parseReport` 校验                                                  |
| `tests/package.test.ts`  | 构建产物通过 SDK 的包校验，契约是 `apiVersion: 3`；四个扩展点的权限；页面引用的文件都在包内；页面不含 SDK 的 schema，分析器页面不含 three.js；`vormio-plugin pack` 生成的包与目录摘要一致                                                                                                                |
| `tests/render.spec.ts`   | 在 Chromium 中运行构建好的页面：贴图在子文件夹且文件名带空格、两个材质库与后者覆盖、贴图选项与 Windows 路径、TGA 与 BMP、顶点颜色与灰色、缺失的材质库、贴图与材质（材质保留颜色）、编译产物与普通文本“不适用”、截断的文件；查看器的三角形与材质数、缺失内容的列表、“不适用”与失败原因；全程没有 CSP 拦截 |
| `tests/analyzer.spec.ts` | 在 Chromium 中运行分析器页面：OBJ 与 MTL 的报告与 Node 中的分析一致并通过 `parseReport`，只读取文件本身；编译产物与普通文本“不适用”；重叠的分析不串                                                                                                                                                      |
